# Двусторонние отзывы

Этап 14 использует существующие reviews, v_user_ratings и v_public_profiles. Новых миграций и зависимостей нет. Один CLIENT может оставлять и получать отзывы в обоих режимах: заказчика и исполнителя.

## Правила и API

Создавать отзыв могут только действующие участники COMPLETED/CANCELLED заказа с активной сессией CLIENT. Автор, получатель, заказ и дата определяются сервером. Получатель — противоположная сторона исходного заказа; повторное назначение проекта не меняет эту связь. Самоотзыв и отзыв по чужому заказу запрещены. UNIQUE(order_id, author_id) допускает максимум один отзыв автора, включая скрытые записи.

| Метод и путь после /api | Назначение |
| --- | --- |
| GET /orders/:orderId/reviews | Публичные отзывы сторон этого заказа, собственный отзыв включая скрытый и возможность создания; только участникам |
| POST /orders/:orderId/reviews | Создание: только rating и text; ответ 201 с review |
| PUT /reviews/:reviewId | Изменение собственного rating/text; ответ 200 с review |
| DELETE /reviews/:reviewId | Мягкое скрытие собственного отзыва; ответ 200 с review |
| POST /reviews/:reviewId/restore | Восстановление той же записи; ответ 200 с review |
| GET /me/reviews | Личные списки: mode=customer/freelancer, direction=received/written |
| GET /users/:userId/reviews | Публичные полученные отзывы: mode=customer/freelancer; сессия не требуется |

rating — целое число 1–5 без приведения строк; text — обязательный текст до 5000 символов, без управляющих символов, с удалением пробелов по краям. Неизвестные поля и параметры отклоняются, включая authorId/recipientId/orderId/status/date/медиа. Пагинация: page 1–10000, pageSize 1–24, по умолчанию 1/12. Личные списки по умолчанию показывают полученные отзывы заказчика; публичные — исполнителя. Сортировка created_at DESC, id DESC стабильна, total сохраняется и за последней страницей. Ответы имеют no-store, изменения ограничены 60 запросами за 15 минут на IP.

Гость для приватной операции получает 401; ADMIN/действующая блокировка — 403; чужой или неизвестный заказ/отзыв — одинаковый 404; активный заказ и повторное создание — 409; неверный ввод — 422. Менять, скрывать и восстанавливать может только автор. Повтор скрытия/восстановления и сохранение неизменённых полей не создают повторных эффектов. Скрытие сохраняет UUID, дату создания и текст; редактирование скрытого отзыва само по себе его не публикует.

## Транзакции, рейтинг и приватность

Порядок блокировок: users по UUID → project → order → review. После ожидания повторно проверяются актуальная роль/блокировка автора, участие, стороны и терминальный статус заказа. Изменение отзыва и REVIEW_CREATED/UPDATED/HIDDEN/RESTORED в audit_logs фиксируются одной транзакцией; ошибка аудита откатывает всё. Параллельное создание имеет одного победителя, встречные отзывы сохраняются отдельно. Заблокированная вторая сторона не лишает активного автора права на отзыв по прежнему заказу.

Среднее и количество считаются PostgreSQL по видимым отзывам отдельно для каждого режима получателя. v_user_ratings используется профилем и поиском исполнителей; публичный список считает те же значения. Скрытие исключает оценку, редактирование и восстановление сразу меняют результат в БД. Уже опубликованный отзыв остаётся после блокировки автора. Публичные отзывы заблокированного получателя или ADMIN скрываются вместе с его публичным профилем.

Публичный DTO содержит rating, text, даты, минимальные имена и ID сторон, контекст получателя и order с id/status. Заголовок, задание, цена, сроки, файлы соглашения, контакты и служебные данные не публикуются. Название заказа и ссылка доступны только в личном списке и карточке заказа его участникам. Скрытый отзыв видит только автор среди своих написанных или в собственном заказе.

## Интерфейс и проверка

Карточка заказа показывает получателя, отзывы и разрешённую сервером форму. Автор может редактировать, подтвердить скрытие и восстановить запись. Ошибка сохраняет введённый текст; если запись уже сохранена, а повторное чтение не удалось, новые команды блокируются до обновления. Навигация «Отзывы» открывает полученные/написанные в обоих режимах с URL-фильтрами и пагинацией. Публичный профиль переключает контексты с отдельным средним и количеством. Для пустых списков, загрузки и ошибок предусмотрены состояния и повтор.

`node scripts/test-infrastructure.mjs`: 77 unit-тестов backend, 100 интеграционных тестов PostgreSQL 17 и 6 тестов API-клиента — 183 всего. Проверены оба источника и терминальных статуса, обе стороны, активные заказы, чужие/неактивные сессии, подмена полей, гонки создания, уникальность после скрытия, изменение рейтинга, все четыре личных списка, публичная приватность/пагинация, новый исполнитель старого проекта, полный rollback всех четырёх операций при сбое аудита и повторная проверка роли после ожидания блокировки. Smoke проверяет операции через frontend proxy и сохранность отзывов/рейтингов после замены контейнеров.

В браузере на отдельной временной базе проверены создание в обоих режимах, правка, скрытие и восстановление, четыре списка, переключение публичного контекста и соответствие рейтингов профиля. Публичная карточка не раскрывает приватное название заказа; ширины 390/1280 px не дают горизонтального переполнения. Тестовые аккаунты и заказы не добавляются в рабочую БД.

Источники поведения: прежние ReviewsViewModel.cs/UserReviewsRepository.cs и согласованные [правила предметной модели](domain-model.md). Сохранены свои/полученные отзывы и авторское управление; Base64-медиа, произвольная смена сторон и системные CUSTOMER/FREELANCER не перенесены. Жалобы и предупреждения относятся к этапу 15.
