# Проекты Workify

Этап 08 добавляет проекты заказчика, каталог открытых заданий, серверные фильтры и вложения через существующий [FileService](files-and-portfolio.md). Используются projects, project_skills, project_files и categories из миграции 001; новых миграций и ролей нет. Заказчик — текущий CLIENT, создающий проект. Администратор просматривает публичный каталог, но не подменяет владельца в клиентских командах.

Этап 09 расширяет карточку [откликами и транзакционным назначением исполнителя](proposals.md). После принятия проект переходит в IN_PROGRESS; обе стороны читают зафиксированные условия и order_files через принятый отклик. Основной CRUD и публичная доступность проекта сохраняют правила этапа 08.

Этап 10 добавляет в собственную карточку историю [приглашений](freelancers-and-invitations.md), а в публичный профиль исполнителя — выбор своего доступного OPEN-проекта. Принятие адресатом создаёт такой же снимок заказа и закрывает несовместимые предложения обоих видов.

## API

| Метод и путь | Назначение |
|---|---|
| GET /api/categories | Публичный справочник `{categories:[{id,slug,name}]}` |
| GET /api/projects | Публичный каталог OPEN активных CLIENT |
| GET /api/me/projects | Свои проекты всех статусов; действующая сессия CLIENT |
| GET /api/projects/:projectId | Публичная карточка OPEN либо своя карточка любого статуса |
| POST /api/projects | Создать DRAFT, 201 `{project}` |
| PATCH /api/projects/:projectId | Изменить переданные поля своего DRAFT/OPEN |
| POST /api/projects/:projectId/publish | Перевести свой DRAFT в OPEN; пустой JSON либо пустой запрос |
| POST /api/projects/:projectId/cancel | Окончательно отменить свой DRAFT/OPEN; `{reason}` |
| DELETE /api/projects/:projectId | Физически удалить свой DRAFT без предметной истории; 204 |
| POST /api/projects/:projectId/files | Прикрепить свою свободную загрузку: JSON `{fileId}` |
| DELETE /api/projects/:projectId/files/:fileId | Убрать вложение из своего редактируемого проекта; `{project}` |

Обычные команды возвращают `{project}`, список — `{items,total,page,pageSize}`. JWT необязателен для каталога и публичной карточки: если он передан, сессия проверяется и isOwn вычисляется сервером. Неизвестный/чужой закрытый проект имеет одинаковый 404 PROJECT_NOT_FOUND. После блокировки или смены роли заказчика на ADMIN его проекты исчезают из публичного каталога и публичной выдачи файлов. Закрытые и выполняемые проекты на этом этапе читает только владелец; будущие API заказов обеспечат доступ участников к снимку соглашения.

DTO содержит id, title, description, status, category, budget, desiredDeadlineAt, skills, files, customer, isOwn, acceptsProposals и даты создания/изменения/публикации. Customer содержит только id, username, имя и фамилию. Контакты, роль, блокировки и credentials не выдаются. Причина/даты отмены и завершения включаются только владельцу. acceptsProposals=true только для OPEN активного CLIENT; для COMPLETED и остальных статусов false. Endpoint создания нового заказа не реализуется на этом этапе: последующие сервисы должны повторно проверять статус под блокировкой.

## Поля и поиск

Создание требует непустой title до 200 символов. Черновик может иметь пустое description (до 10000), categoryId=null, budget=null и desiredDeadlineAt=null. При публикации обязательны категория и непустое описание; заданный желаемый срок должен быть в будущем. Из опубликованного задания нельзя удалить описание или категорию. Навыки — до 20 уникальных UUID существующего справочника, fileIds — до 8 собственных файлов. Все неизвестные поля, включая customerId, status и служебные даты, отклоняются с 422. Владелец и начальный статус назначаются сервером.

Budget передаётся положительным десятичным числом или строкой, до 9999999999.99 и двух знаков после точки; API возвращает строку с двумя знаками, без потери точности NUMERIC. Валюта и платежи не вводятся. DesiredDeadlineAt — корректная ISO 8601 дата с часовым поясом; сервер нормализует UTC. Новый/изменённый срок должен быть в будущем; неизменённый истёкший срок не мешает частичному редактированию других полей. Описание разрешает переносы и табуляцию, управляющие символы/NUL запрещены. React отображает текст без исполнения HTML.

PATCH сохраняет пропущенные значения; явный null очищает необязательные условия, пустые массивы очищают навыки/вложения. Пустой PATCH отклоняется. Проверки справочников, файлов и обновление всех связей атомарны. При неверном UUID не сохраняется даже часть команды.

Списки принимают search (до 100 символов, буквальная подстрока заголовка/описания без учёта регистра), category/skill (slug), minBudget/maxBudget, sort, page и pageSize. Бюджетные границы включительные; при их наличии проекты без бюджета не попадают в результат. Sort: newest, oldest, budget_asc, budget_desc, deadline_asc; неизвестные бюджеты/сроки идут последними. Для одинаковых значений используется id как стабильный второй ключ. Newest/oldest в каталоге используют published_at, у своих проектов — created_at. По умолчанию page=1, pageSize=12; допустимы 1–10000 и 1–24. Только /me/projects дополнительно принимает status из DRAFT/OPEN/IN_PROGRESS/COMPLETED/CANCELLED.

Все условия применяются PostgreSQL, включая поиск, фильтрацию, сортировку и пагинацию; total и страница читаются одним запросом/снимком. За пределами последней страницы items пуст, total сохраняется. Значения параметризованы, SQL ORDER BY берётся только из внутреннего whitelist. Дубли query-параметров и произвольные поля отклоняются. Поиск подстрокой выбран для предсказуемого поведения небольшого каталога курсовой; морфологический полнотекстовый поиск не включён.

## Состояния, права и файлы

Изменяющая транзакция сначала блокирует users текущего CLIENT и повторно проверяет его роль/блокировку, затем свой projects и при необходимости файлы. Чужая команда получает 404. Публикация допустима только из DRAFT; повторная публикация — 409 PROJECT_STATE_CONFLICT. Редактирование и отмена допустимы только из DRAFT/OPEN без активного или завершённого заказа. IN_PROGRESS/COMPLETED/CANCELLED не возвращаются в OPEN через CRUD. Физическое удаление допустимо только для DRAFT без proposals/invitations/orders; в остальных случаях используется отмена с непустой причиной до 1000 символов.

Реальное изменение задания, условий, навыков или вложений OPEN закрывает все PENDING proposals как REJECTED и invitations как EXPIRED с closure_reason=TERMS_CHANGED и decided_at в той же транзакции. Повтор прежних значений и перестановка UUID не закрывают предложения. Окончательная отмена закрывает pending с PROJECT_CANCELLED, записывает cancelled_at/причину и сохраняет историю. Прошлые источники и заказы не удаляются; события/уведомления будут расширены соответствующими этапами. Лимит создания — 100 проектов на CLIENT, изменений — 60/15 минут на IP; для текущего proxy это общий IP, как у остальных модулей.

Загрузка выполняется POST /files через Multer/FileService, затем UUID связывается с проектом отдельной командой либо атомарно вместе с create/PATCH.fileIds. Чужой/занятый файл не прикрепляется. Файл DRAFT доступен только загрузившему владельцу; файл OPEN активного клиента публичен через GET /files/:id. После отмены/начала выполнения/завершения публичный доступ закрывается, право владельца сохраняется. Физический uploadDir по HTTP не раздаётся.

Снятие вложения или удаление черновика фиксирует deleted_at только для файлов без других ссылок, затем FileService удаляет объект из volume с повтором после сбоя. Файлы, сохранённые в order_files для будущего снимка соглашения, не будут удалены при изменении проекта. Отмена проекта не удаляет его вложения. Свободные загрузки после отмены формы остаются в личном разделе файлов и могут быть повторно использованы или удалены.

## Интерфейс и проверка

Страницы: /projects — каталог; /me/projects — свои проекты; /projects/new и /projects/:id/edit — формы; /projects/:id — карточка. Фильтры сохранены в URL, работают после reload и отправляются серверу. В карточках показаны статус, категория, навыки, бюджет, желаемый срок и отметка «Ваш проект». Форма отправляет только изменённые поля, сохраняет черновик при ошибке и показывает последствия изменения опубликованных условий. Публикация выполняется из карточки; отмена требует причины, удаление черновика — отдельного подтверждения в интерфейсе.

`node scripts/test-infrastructure.mjs`: 74 unit-теста backend, 90 интеграционных тестов PostgreSQL 17, 6 тестов API-клиента, сборка React и реальные проверки через proxy. Проверены whitelist, точность бюджета, даты, приватность, чужие UUID, частичные изменения/откат, публикация, поиск/фильтры/пагинация, закрытие pending, terminal статусы, файлы, блокировки, конкурентные PATCH и публикации. Smoke создаёт/публикует проект с файлом, проверяет фильтры/isOwn, принимает отклик и проверяет сохранность условий/вложений/заказа после реальной замены контейнеров. Рабочие volumes автоматическим набором не используются. Новых DDL нет; runner также проверяет применение прежних четырёх миграций на чистой базе. Согласованная работа доступна участникам в [разделе заказов](orders.md).

В браузере проверены создание с TXT-вложением, публикация, редактирование бюджета, поиск/сортировка, отметка владельца, выход и гостевой каталог; на ширине 390 px горизонтального переполнения нет. Дополнительно проверен выход в другой вкладке: закрытая карточка очищается и показывает 404 без прежнего содержимого. Временный QA-аккаунт, его проекты и файлы удаляются после проверки. Источники: ООП ProjectsViewModel.cs и UserProjectRepository.cs, текущие 08_rest_api.md и 17_permissions_matrix.md, [согласованные переходы](state-transitions.md). Сохранены свои/общие проекты и CRUD; произвольный статус из WPF, автоматическое создание order при отклике, EF и Base64 не переносятся.
