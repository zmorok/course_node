# Журнал аудита

Значимые изменения аккаунтов, проектов, откликов, приглашений, заказов, версий, сроков, отзывов, жалоб и санкций записываются в `workify.audit_logs`. Единственная точка INSERT — `createAuditRepository().audit`; запись выполняется в транзакции изменения. Ошибка аудита откатывает операцию. История заказа остаётся отдельной в `order_events`.

Запись содержит автора (либо NULL для операторской команды), действие, тип и ID объекта, время PostgreSQL, дополнительные данные и при необходимости значения до/после. HTTP-контекст добавляет серверный requestId и адрес непосредственного соединения. Заголовкам произвольного прокси приложение не доверяет; в Docker адрес может принадлежать frontend proxy.

Пароли, токены, cookie, ключи, хеши и секреты исключаются рекурсивно при записи и чтении. Метаданные ограничены по глубине и длине. Поиск не просматривает произвольное содержимое JSON. Сам журнал предназначен только ADMIN и может содержать приватные данные изменённого профиля. Публичный профиль контакты не раскрывает.

`GET /api/admin/audit` принимает `search`, `actorId`, `action`, `entityType`, `entityId`, `createdFrom`, `createdTo`, `sort=newest|oldest`, `page`, `pageSize` (до 24). Возвращает `items`, `total`, `page`, `pageSize`; сортировка стабильна по времени и UUID. UI находится по `/admin/audit`. POST/PATCH/DELETE API отсутствуют; триггер БД запрещает изменение и удаление записей. Старые записи без IP сохраняются.

Успешные регистрация, вход, ротация refresh и выход журналируются без реквизитов входа. Повторное использование refresh фиксируется после отзыва сессии. Вход повторно читает пользователя под блокировкой; refresh, модерация и изменение профиля используют порядок блокировок пользователь → сессия. Команда повышения ADMIN записывает `ADMIN_GRANTED` с системным автором в одной транзакции с повышением.

Проверки: 89 backend unit, 133 integration и 6 frontend unit (228 всего), включая фильтры и страницы, приватность, очистку старых JSON, неизменяемость, откат, гонки входа/refresh с блокировкой. Docker smoke проверяет журнал через frontend proxy и сохранность ID и снимков после замены контейнеров.
# Обмен JSON — этап 25

`GET /api/admin/audit/export` выгружает журнал с текущими фильтрами (до 5000 событий и 2 МБ). `POST /api/admin/audit/import` принимает один multipart-файл `file`, JSON до 2 МБ: контейнер `{format:"workify-audit",version:1,entries:[...]}` либо массив прежних WPF-записей с `action` и `changed_at`. Некорректный архив отклоняется целиком, повторные записи не дублируются, поля credentials удаляются рекурсивно.

Внешние события доступны в отдельном неизменяемом архиве `GET /api/admin/audit/imported`. Они не подменяют действия текущего приложения и не требуют совпадения старых идентификаторов пользователей. Импорт, его автор и количество принятых записей фиксируются в основном аудите. Все операции доступны только ADMIN; при записи роль повторно проверяется в транзакции.
