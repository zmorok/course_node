## Изменения

- Единая оболочка: шапка 82 px, контейнер до 1320 px, боковая навигация 240 px, мобильное меню с закрытием по переходу, Escape и нажатию снаружи. Состав навигации определяется реальной ролью CLIENT/ADMIN.
- Экспортированные семантические токены в `frontend/src/tokens.css`, обе темы, локальный Inter 4.1 с кириллицей, логотипы и SVG Heroicons. Визуальные состояния элементов используют общие правила в `styles.css`.
- Каталог проектов и исполнителей, карточки, раскрывающиеся фильтры, публичный профиль, портфолио, страницы проекта и редактор, заказы и история, отклики и приглашения, отзывы, жалобы, уведомления, предупреждения, формы профиля и безопасности, административные списки, формы и аудит приведены к общей системе.
- В собственном профиле данные, безопасность и портфолио доступны через переключатели. Формы остаются смонтированными при переключении, поэтому введённые значения сохраняются.
- Приглашение из публичного профиля раскрывается по кнопке. Оно использует существующую форму, условия и API. Обложки работ берутся из реальных image attachments; PDF-only работы не получают вымышленную картинку. Демонстрационный арт Figma в приложение не переносился.
- После входа из проекта или публичного профиля выполняется возврат на исходную страницу. Адрес возврата проверяется существующим `isAppUrl`; внешние адреса не принимаются.
- Рабочий экран заказа начинает со статуса и действий. Существующие проверки `order.permissions`, подтверждения, версии, сроки, отмена, отзывы и жалобы сохранены.
- Порядок мобильного заказа соответствует спецификации: состояние/действие → условия/участники → соглашение/файлы → версии/сроки → история. Этот порядок совпадает с порядком DOM. Действия сдачи и переноса срока переводят фокус в открываемую форму.
- Экран аккаунта после входа использует рабочий каркас и карточку аккаунта, без большого приветственного блока. Сохранены обновление данных, выход, проверка подключения и административная проверка доступа.

Сервер, база, маршруты API, их схемы, проверки прав и бизнес-переходы не менялись. Сохранены SPA-навигация, восстановление сессии, обработка ошибок, загрузки и авторизованное скачивание вложений. Пользовательские данные не подменены данными макетов. Примеры в браузерных проверках изолированы в тестах.

## Адаптивность и проверка

Основные ширины: 1440, 768, 390 и 320 px. До 1200 px используется компактная шапка с меню; до 900 px фильтры раскрываются по кнопке и основные колонки перестраиваются; до 768 px формы, действия и карточки переходят в мобильную компоновку. Длинные названия, ссылки, имена файлов и JSON переносятся внутри блока.

Проверено Node 24.22.1:

- `npm run build` — успешно. Vite сообщает о едином JS-чанке свыше 500 kB; ошибка сборки отсутствует.
- `npm test` — 15/15.
- `npx playwright test --reporter=line --workers=4` — 30/30, Chromium. Из них 9 прежних сценариев SPA и 21 проверка оформления/действий.
- 16 клиентских и 4 административных маршрута на четырёх ширинах, Light/RU и Dark/EN: 160 представлений без горизонтального переполнения и необработанных ошибок.
- Дополнительно: раскрытие меню и фильтров; сохранение значений при смене языка/темы; формы регистрации и приглашения на 320 px; ограничения ролей; сдача версии с введённым содержимым; вход с возвратом; запрет внешнего возврата; реальные image attachments и PDF-only работы.
- Проверены порядок блоков заказа, перевод фокуса в формы сдачи/срока, приёмка заказчиком с подтверждением на 320 px, административные карточки/формы санкций и решения по жалобе, обновление аккаунта и выход. После этих уточнений весь прогон выполнен повторно: 30/30 за 1,8 минуты.
- Сохранены 24 полных снимка трёх опорных экранов в `runtime/design-review/`. Вручную просмотрены desktop/mobile каталог, профиль и заказ, а также планшетный каталог в тёмной теме. `git diff --check` — без замечаний.

Браузерные проверки используют контролируемые API-ответы. При первичной визуальной проверке рабочие backend/БД не запускались. При последующей сверке с листом задания выполнен отдельный успешный прогон `scripts/test-infrastructure.mjs` с реальными API и PostgreSQL в изолированном Compose: 246 unit/integration-тестов, HTTP E2E и восстановление сервисов. Существующие пользовательские записи не изменялись. Safari/Firefox в этом прогоне не проверялись.

Новые анимации, донорские таблицы, переименование пакета и финальный промпт для вёрстки не выполнялись — это отложенная пользователем второстепенная часть.
