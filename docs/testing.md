# Проверка и демонстрация релиза 1.1.0

Из корня приложения с Node.js и работающим Docker Engine:

```powershell
node scripts/test-database.mjs
node scripts/test-infrastructure.mjs
```

Первый runner проверяет PostgreSQL 17: чистую установку, восемь миграций, повторное применение/seed, 57 ограничений, представления, рейтинги, откат ошибочной миграции и конкуренцию proposal/invitation. Второй проверяет генерацию `.env` на временной копии, собирает Compose с нуля, запускает 90 backend unit, 141 integration и 15 frontend unit — 246 тестов — и выполняет HTTP E2E через реальный frontend proxy. Наборы не используют рабочую БД и не удаляют рабочие volumes; свои ресурсы удаляют в finally. Новый запуск создаёт отдельный проект со случайными секретами и свободными loopback-портами.

HTTP E2E автоматически проверяют весь серверный путь через frontend proxy. Отдельный Playwright-набор проверяет UI с подменённым API, поэтому не заменяет серверные интеграционные тесты. WebSocket в проект не включён.

Браузерные проверки SPA (этап 28), из каталога `frontend`:

```powershell
npm ci
npx playwright install chromium
npm run test:browser
```

Runner собирает production frontend и запускает его preview на свободном для этой проверки порту 5174 (занятый порт считается ошибкой). Проверяются девять сценариев: каталог/фильтры/пагинация/история; режимы заказов с сохранением сессии; разные ID карточек и обновление прямого адреса; язык/тема и значения регистрации; создание/удаление проекта; выход после смены пароля; язык статусов и несохранённый фильтр; язык уже показанной ошибки формы; редактирование/удаление жалобы. Счётчик навигационных запросов подтверждает один HTML-документ на сценарий, кроме явной проверки обновления вкладки. Переключение языка/темы в форме регистрации не отправляет запросы. Трассы при ошибках сохраняются в игнорируемом `runtime/spa-browser-results`.

Для установленного Chrome можно задать `$env:PLAYWRIGHT_CHANNEL='chrome'`; по умолчанию используется загруженный Chromium. Рабочие аккаунты, файлы и БД браузерными фикстурами не изменяются. Отдельная проверка запущенного Docker-интерфейса с реальным API подтверждает переходы каталога/исполнителей, «Назад», язык, тему и сохранение поля регистрации без отправки формы.

Для демонстрации запустите приложение по [README](../README.md), зарегистрируйте двух CLIENT в разных профилях браузера и третьего пользователя для ADMIN. Повысьте третьего по [инструкции оператора](auth.md), затем выполните обязательный сценарий из таблицы. Заказы доступны в режимах «Как заказчик» и «Как исполнитель»; ссылки на отзывы, жалобы и предупреждения находятся в меню «Ещё», уведомления — в основной навигации. Для показа повторного назначения используйте отдельный активный заказ: завершённый заказ не отменяется.

Границы курсового: платежи, email/push, Redis, MinIO, микросервисы и обязательный Nginx отсутствуют. Локальный Compose публикует порты только на 127.0.0.1. Для размещения за HTTPS включите Secure cookie согласно инструкции инфраструктуры. Секреты и пользовательские загрузки не входят в Git; резервное копирование рабочих volumes выполняется отдельно от тестов.
