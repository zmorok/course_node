# Уведомления

Постоянные уведомления хранятся в существующей таблице `workify.notifications` PostgreSQL. Они создаются в транзакциях предметных операций: новый отклик/приглашение и изменение их статусов, создание заказа для обеих сторон, запрос/решение срока, сдача, доработка, приёмка, отмена и решение по жалобе. Неявное закрытие источников при изменении проекта также уведомляет исполнителей. Откат операции откатывает её уведомления.

Для текущего авторизованного пользователя:

- `GET /api/me/notifications?read=all|unread|read&page=1&pageSize=12` — список, `total`, `unreadCount` по всем своим событиям, текущая страница и её размер (максимум 24). Порядок: время и UUID по убыванию.
- `GET /api/me/notifications/unread` — собственный счётчик.
- `POST /api/me/notifications/:notificationId/read` с `{}` — идемпотентная отметка; сохраняет первоначальное `readAt`. Чужой и неизвестный ID возвращают одинаковый 404.
- `POST /api/me/notifications/read-all` с `{}` — отмечает существующие непрочитанные события только текущего получателя. Возвращает количество обновлений. Более поздние события остаются непрочитанными.

Изменяющие запросы требуют `X-Workify-Client: browser`. Получатель берётся из серверной сессии; параметры recipientId и произвольные поля запрещены. Ответы имеют `Cache-Control: no-store`, не раскрывают внутренние metadata и данные других получателей. Ссылка на предметный раздел формируется сервером, а доступ к нему повторно проверяется обычным API.

В `/me/notifications` доступны фильтры, страницы, повторная загрузка, пустое состояние и отметки прочтения. Счётчик в навигации и открытый список обновляются раз в минуту; счётчик также обновляется при возвращении фокуса и после отметки. WebSocket/email/push не используются. Предупреждения администратора по-прежнему доступны отдельно в `/me/warnings`; уведомление лишь ведёт в этот раздел.

Интеграционные проверки покрывают все требуемые типы, изоляцию получателей, фильтры, стабильные страницы, повторные отметки, новые события после read-all, CSRF, блокировки и откат. Docker smoke дополнительно проверяет сохранность UUID и времени прочтения после пересоздания контейнеров.
