# Проверка и демонстрация релиза 1.1.0

Из корня приложения с Node.js и работающим Docker Engine:

```powershell
node scripts/test-database.mjs
node scripts/test-infrastructure.mjs
```

Первый runner проверяет PostgreSQL 17: чистую установку, восемь миграций, повторное применение/seed, 57 ограничений, представления, рейтинги, откат ошибочной миграции и конкуренцию proposal/invitation. Второй проверяет генерацию `.env` на временной копии, собирает Compose с нуля, запускает 90 backend unit, 141 integration и 8 frontend unit — 239 тестов — и выполняет HTTP E2E через реальный frontend proxy. Наборы не используют рабочую БД и не удаляют рабочие volumes; свои ресурсы удаляют в finally. Новый запуск создаёт отдельный проект со случайными секретами и свободными loopback-портами.

| Область | Проверка |
|---|---|
| Обязательный сценарий | `backend/test/integration/course-e2e.test.js`: A и B регистрируются → проект → отклик → принятие → сдача → доработка → новая версия → приёмка → два отзыва → жалоба → ADMIN рассматривает и выдаёт warning → получатель читает warning. Каждый шаг проверяет HTTP-результат и состояние |
| Приглашение и повторное назначение | Второй course E2E: приглашение → принятие → отмена → проект OPEN → новый отклик и заказ с C; старые условия/файлы/стороны сохраняются, доступ между заказами изолирован |
| Конкуренция | `invitations.test.js`, `proposals.test.js`, `order-work.test.js`, `order-completion.test.js`: одновременные принятия, смешанные источники, сдача/решение/отмена, один согласованный результат и rollback поздней ошибки |
| Права и вход | auth/profile/files/projects/orders/reviews/complaints/admin/audit integration: гости, чужие UUID, CLIENT/ADMIN, блокировки, смена роли после ожидания lock, отзыв JWT, refresh replay, приватность контактов/файлов/жалоб |
| Загрузки | `files.test.js`: размер больше 10 MiB, пустые/неподдерживаемые/замаскированные файлы, traversal, посторонние multipart-поля и откат без метаданных/байтов |
| Уведомления и аудит | Свой получатель, непрочитанные/прочтение, стабильные страницы, отсутствие credentials, неизменяемый audit, снимки до/после, rollback и гонки с блокировкой |
| Полная инфраструктура | `scripts/test-infrastructure.mjs`: React assets, API и HttpOnly cookie через proxy; соглашения, файлы, версии, отзывы, жалобы, warnings, audit и read_at переживают реальную замену контейнеров; БД и proxy восстанавливаются после остановки сервисов |
| Интерфейс | Проверка в браузере списка/карточки заказа, версий/сроков/событий, жалоб, формы отзыва, меню и ошибок; ширины 390/1280 без горизонтального переполнения. Регистрация 1920×960 без вертикальной прокрутки |

HTTP E2E автоматически проверяют весь серверный путь через frontend proxy; проверки UI выполнялись отдельно в браузере. WebSocket и автоматизированный Playwright-runner в проект не включены.

Для демонстрации запустите приложение по [README](../README.md), зарегистрируйте двух CLIENT в разных профилях браузера и третьего пользователя для ADMIN. Повысьте третьего по [инструкции оператора](auth.md), затем выполните обязательный сценарий из таблицы. Заказы доступны в режимах «Как заказчик» и «Как исполнитель»; ссылки на отзывы, жалобы и предупреждения находятся в меню «Ещё», уведомления — в основной навигации. Для показа повторного назначения используйте отдельный активный заказ: завершённый заказ не отменяется.

Границы курсового: платежи, email/push, Redis, MinIO, микросервисы и обязательный Nginx отсутствуют. Локальный Compose публикует порты только на 127.0.0.1. Для размещения за HTTPS включите Secure cookie согласно инструкции инфраструктуры. Секреты и пользовательские загрузки не входят в Git; резервное копирование рабочих volumes выполняется отдельно от тестов.
