# Workify

Курсовой проект «Веб-приложение для управления проектами и заказами на IT-фриланс-площадке».

Workify объединяет публикацию IT-проектов, подбор исполнителя через отклик или приглашение, выполнение заказа, сдачу версий результата, согласование сроков, отзывы и административное рассмотрение жалоб.

## Состояние проекта

Этап 01: спецификация предметной области до написания приложения.

- [Роли, сущности, связи, требования и матрица прав](docs/domain-model.md).
- Git инициализирован с основной веткой `main`; этап разрабатывается в `stage/01-domain-model`.
- Следующий этап — проектирование PostgreSQL 17. Код приложения, миграции и Docker Compose пока не созданы; команды запуска появятся вместе с работающей инфраструктурой.

## Согласованный стек и границы

- JavaScript, React, Node.js + Express, PostgreSQL 17, Docker Compose.
- Backend: `routes -> controllers -> services -> repositories/DAO -> PostgreSQL`; SQL выполняется через `pg` в repositories/DAO, бизнес-правила находятся в services.
- Системные роли: `CLIENT`, `ADMIN`. Заказчик и исполнитель — режимы одного `CLIENT`, определяемые его участием в конкретном проекте или заказе.
- Multer и общий FileService; файлы хранятся в Docker volume `uploads_data`, PostgreSQL хранит метаданные и связи.
- Платежи оставлены для диплома. Redis, MinIO, микросервисы и обязательный Nginx в объём курсового не входят.

## Работа с Git

Каждый этап выполняется в отдельной ветке от `main`. После проверок он вливается через `git merge --no-ff` и отмечается аннотированным тегом `stage-NN-complete`. Основной журнал изменений — история Git.

Содержательные коммиты имеют один префикс слоя: `UI:`, `Back:`, `DB:`, `Infra:`, `Test:` или `Docs:` и понятное описание на русском языке. Секреты, `.env`, зависимости, результаты сборки и загруженные пользователями файлы исключены из Git. Безопасные `.env.example` допускаются.
